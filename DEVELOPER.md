# Разработка Karaoke Sync Studio

## Архитектура

Проект совмещает React-интерфейс, локальный Express-сервер и Electron-оболочку:

```text
React UI ──HTTP──> Express API ──> Gemini
   │                   │
   ├─ localStorage     └─ dist/server.cjs
   ├─ IndexedDB
   └─ preload IPC ──> Electron main process
```

- `src/` — интерфейс, редактор, хранение браузерных данных и экспорт;
- `shared/` — синхронизация, типы и canvas-рендеринг, используемые клиентом и сервером;
- `server/` и `server.ts` — API распознавания и раздача production-сборки;
- `electron/` — main process, preload и Windows-ресурсы;
- `public/` — статические файлы, копируемые Vite в `dist/`;
- `assets/branding/` — мастер-ресурсы бренда, не используемые напрямую в runtime.

## Команды

```powershell
npm install
npm run dev
npm run lint
npm run build
npm run electron
npm run dist:electron
```

Тесты запускаются через встроенный Node.js test runner:

```powershell
$testFiles = @(rg --files -g '*.test.ts')
node --import tsx --test $testFiles
```

## Конфигурация

- Сервер читает `GEMINI_API_KEY` из `.env`.
- В Electron сначала проверяется `.env` рядом с EXE, затем файл в `app.getPath('userData')`.
- Порт Electron по умолчанию фиксирован: `17842`. Это сохраняет origin для `localStorage` и IndexedDB.
- Если порт занят, выбирается временный свободный порт; данные такого origin не считаются постоянным проектным хранилищем.

## Хранение данных

- настройки и активный проект — `localStorage`;
- оригинальный аудиофайл, фон и изображения брендинга — IndexedDB;
- пресеты экспортируются в `*.karasync-preset.json`;
- строки являются источником истины для плоского списка слов: перед сохранением
  и восстановлением список собирается из `lines`, без дополнительных слов;
- самостоятельное тире прикрепляется к предыдущему слову и не хранит таймкод;
- пользовательские медиа и ключи не должны добавляться в Git или релизный архив.

## Правка начала слова на звуковой волне

`WaveformTimeline` виден под основным плеером и использует WaveSurfer с общим
`HTMLAudioElement` исходной песни для воспроизведения. Если при транскрибации
загружен чистый вокал, он отдельно сохраняется в IndexedDB и декодируется
только для изображения волны. В памяти остаются лишь пики с шагом 5 мс;
после перезагрузки волна восстанавливается из сохранённой дорожки.
Пики вокала раскладываются по временной шкале оригинала без растягивания:
недостающая часть заполняется тишиной, лишняя обрезается. Без вокальной дорожки
показывается волна исходной песни с явной подписью источника. Чистый вокал можно
заново прикрепить прямо над волной без повторной транскрибации; файл сохраняется
в IndexedDB. Повторная попытка после ошибки транскрибации использует тот же
вокальный файл, чтобы не очистить сохранённую дорожку. WaveSurfer получает
фиксированный пик всей вокальной дорожки для нормализации: тихие участки не
усиливаются отдельно при прокрутке по чанкам canvas. Плагин Regions ставит на начало каждого
слова перетаскиваемый маркер; его подпись и шкала времени прокручиваются
вместе с волной. Масштаб
задаётся в пикселях на секунду. WaveSurfer получает готовые данные волны без
повторного декодирования и всегда использует URL оригинала для воспроизведения.

После отпускания маркера `moveWordStart` обновляет слова и строки одним
изменением истории Undo/Redo. Начало ограничено соседними началами, а конец
затронутого слова при необходимости корректируется для валидности старого
формата таймингов. Цвет слова в предпросмотре и экспорте переключается только
по `start`; отдельный маркер конца на волне не требуется.
Контекстное меню маркера удаляет выбранное слово из строки и плоского списка
одним действием Undo/Redo. Текст и временные границы строки пересчитываются;
пустая строка удаляется. Сохранённый проект с пустым списком слов также
восстанавливается без повторного появления удалённых слов.
Кнопки общего сдвига перемещают все таймкоды слов на 50 или 100 мс за одно
действие Undo/Redo; сама звуковая волна остаётся на месте.
Компактная карточка выбранного слова находится под волной. В одной строке
расположены название в поле постоянной ширины, переход к соседним словам,
воспроизведение, время начала и сдвиги на 50/100 мс. Переход использует ту же
навигацию, что основной плеер; длина слова не двигает кнопки правки. Кнопка
воспроизведения запускает оригинальную песню с начала выбранного слова до
начала следующего слова, независимо от длины промежутка; у последнего слова
играет до конца дорожки. Затем воспроизведение останавливается и курсор
возвращается к началу выбранного слова. Повторное нажатие во время звучания
делает то же сразу, не меняя таймкоды. Управление воспроизведением, повтором
и сдвигом строк в редакторе убрано. Ниже волны остаётся список слов с поиском,
который фильтрует и строки, и сплошной поток. Во время воспроизведения список
прокручивается внутри своего блока к текущей строке или слову; при паузе и поиске прокрутка остаётся
ручной. Кнопка под плеером скрывает и волну, и список. Размер окна предпросмотра
регулируется ползунком рядом со скоростью воспроизведения и сохраняется отдельно
от проекта; размер экспортируемого видео не меняется. Рядом расположен вход в
полноэкранный предпросмотр. Сохранение и загрузка пресетов оформления доступны
в верхней панели; их диалог и файловый ввод остаются внутри `VideoPreview` и
вызываются через его ref. Вместо счётчиков строк и слов в верхней панели
расположены снимок кадра и три кнопки настроек предпросмотра. Заголовок над
кадром и отдельный переключатель его панели убраны. Отмена и повтор действий
доступны через кнопки над волной и горячие клавиши. После удаления последнего
слова редактор остаётся открытым, пока действие можно отменить.

## Production и Electron

`npm run build` выполняет два шага:

1. Vite собирает React в `dist/` и копирует туда содержимое `public/`.
2. esbuild создаёт `dist/server.cjs` для локального production-сервера.

Electron запускает сервер на loopback-интерфейсе, ждёт `/api/health`, затем открывает `BrowserWindow`. Внешняя навигация блокируется и передаётся системному браузеру. Renderer работает с `contextIsolation`, без `nodeIntegration`, с sandbox.

## Сборка релизного установщика

Версия синхронизируется в `VERSION`, `package.json`, `package-lock.json` и `RELEASE_NOTES.md`.
Диалог «О программе» берёт версию из `app.getVersion()`; кнопка «Заметки о выпуске» открывает упакованный вместе с приложением `RELEASE_NOTES.md`.
Каждый выпуск в `RELEASE_NOTES.md` оформляется как `## Версия X.Y.Z (YYYY-MM-DD)`, затем идёт краткое курсивное резюме и разделы `### ✨ Новые возможности`, `### 🐛 Исправления ошибок`, `### 🛠 Улучшения` или другие подходящие разделы с иконками. Текст пунктов описывает изменения для пользователя; технические проверки размещаются отдельно.
Описание GitHub Release содержит только текущую версию в том же формате, ссылку на установщик и ссылку на полную историю изменений в `main`. После публикации проверьте отображение Markdown на GitHub; если скрипт публикации вставил весь журнал, замените описание текущим выпуском.
`package-lock.json` — поддерживаемый lock-файл проекта; зависимости устанавливаются через npm.
Windows-сборка использует локальный runtime из `node_modules/electron/dist`, чтобы упаковщик не переименовывал временную папку распаковки Electron. Поэтому перед сборкой нужны установленные dev-зависимости.

Последовательность подготовки Windows-установщика:

1. Запустить тесты, `npm run lint`, `npm run build` и проверку зависимостей.
2. Создать release commit и теги `vX.Y.Z` плюс следующий числовой тег.
3. Удалить только точную старую папку `Karaoke-Sync-Studio-X.Y.Z`, если она существует.
4. Выполнить `npm run dist:electron`. Команда собирает `win-unpacked` через
   electron-builder, проверяет `app.asar` и production-сервер неинтерактивно через
   Electron в Node-режиме (`npm run smoke:frozen`), затем компилирует `scripts/KaraokeSyncStudio.iss` через
   `scripts/build-installer.ps1` и Inno Setup 6. Компилятор задаётся через
   `INNO_SETUP_ISCC`, либо находится в PATH или стандартных каталогах установки.
   Установщик сохраняется на
   реальном рабочем столе пользователя; portable-папка остаётся в каталоге сборки.
5. Проверить `app.asar`, версию и системные иконки EXE, содержимое установщика и
   неинтерактивный frozen-smoke. Сборка и проверка не запускают окно программы.

Установщик использует только русский язык и предлагает `D:\Apps\Караоке Синк Студио`,
если диск D существует, иначе `C:\Apps\Караоке Синк Студио`. Он не использует
прошлый путь установки. Финальная галочка «Запустить приложение» отмечена по
умолчанию для пользователя, но релизный процесс сам установщик не запускает.

Установщики, распакованные сборки, `.env`, `node_modules`, `dist` и другие generated/runtime-файлы не коммитятся. Portable-архив не создаётся без отдельного запроса.
